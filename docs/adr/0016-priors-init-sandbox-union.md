# Python `priors_init`: copy missing factory names; classify dummy generate

`priors_init` treated overlapping names in a shared Input catalog directory as “already complete”, so a later configuration (e.g. qso after gal) never received extra `.iprior` files. Dummy generation swallowed every binary exit and capped at 10 rounds. We decide: after the current configuration’s factory set in `{outdir}/priors_defaults/` is known, copy only missing basenames beside the catalog, never overwrite. Dummy generate stops on binary output (Z4): `Can't open` + template written + new files → continue; rc=0 + `No valid objects` + no new files → done; anything else raises; no round cap. We rejected a `.complete` marker, moving generate out of the catalog directory, and changing `regenerate_defaults` overwrite behavior in this cut.
