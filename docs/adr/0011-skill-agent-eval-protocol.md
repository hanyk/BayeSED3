# Skill agent eval: reliability first, then efficiency; argv + science hard gates

We evaluate whether the BayeSED3 agent skill (`skills/SKILL.md`) can guide an AI agent through a full Bayesian SED workflow by scoring **agent behaviour**, not skill prose. Correctness is a hard gate before efficiency: Prefer the Interfaces table (`SEDInference` for ordinary new fits; Inspect for an existing outdir; `bayesed3 run` only for binary-only argv / `--import`). Efficiency compares paths on **token count and tool rounds** (session wall clock secondary; binary fit wall clock is a control only—same Model configuration should be similar). Both `observation/test/gal.txt` and `observation/test/qso.txt` are required fixtures (qso is mandatory complexity). Python vs `bayesed3 run` consistency is a hard gate: normalize and compare argv from internal `to_cli_args(params)` against `bayesed3 run` argv (ignore Launcher-owned `--mpi` / `--np`); `Ntest` is a binary flag on `BayeSEDParams` (`to_cli_args` emits `--Ntest`); `inference.run(..., Ntest=)` / `BayeSEDInterface(Ntest=)` override `params.Ntest` before serialization so A/B needs no special case; fix the same MultiNest `seed` (≥0); require Evidence within `max(0.05, 2·√(σ₁²+σ₂²))` using each side’s `log_evidence_error` (or Inspect err columns), and key free-parameter medians within the larger 68% posterior width; when normalized argv match exactly, apply a stricter near-identity bar. The agent under test must not explore the codebase to learn the workflow: only the skill tree (`skills/SKILL.md` + `skills/references/*`), the installed `bayesed` package (import / run / Inspect), and the fixed fixtures / prompt. Searching or reading `bayesed/*.py`, `tests/`, or ADRs to discover how to fit is a correctness failure (or a severe protocol violation). Scorers may still use `to_cli_args` and Evidence diffs outside the agent session. We rejected treating `bayesed3 run` as the default efficiency winner, using fit wall clock as the primary efficiency metric, soft-failing scientific disagreement, and building an automated harness before a manual playbook proves useful. Executable steps live in `docs/agents/skill-eval.md`. Phase 1 (2026-09-18) closed the manual board (tasks 1–5 + Consistency A/B gal/qso); findings and the operator “how to run” checklist live in that playbook. A product gap found during Consistency A/B (`params.Ntest` silent in `to_cli_args`) is decided in ADR-0012.
