# Runtime bootstrap adapter outside BayeSEDInterface

OpenMPI discovery/install, scheduler-aware process count, host OS/arch validation, and binary path resolution live in an internal `bayesed.runtime` module (`resolve_system_info`, `resolve_mpirun`, `resolve_num_processes`, `resolve_executable`). `BayeSEDInterface` calls these at init and when auto MPI mode re-resolves the executable; it no longer owns `_setup_openmpi` / `_get_max_threads` / `_get_executable` / `_get_system_info`. The adapter is not exported from the public `bayesed` package. MPI mode selection (`_select_mpi_mode`) stays on the interface — that heuristic is scientific strategy, not platform bootstrap. We rejected a thin private middle-man on the interface, a public runtime export, and folding mode selection into `runtime`.
