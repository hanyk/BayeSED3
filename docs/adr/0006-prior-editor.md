# PriorEditor for interactive edit and presentation

Interactive prior edit/query/print (`set_prior`, `print_priors`, and the prior table) lives in an internal `bayesed.prior_editor.PriorEditor`. After a successful `priors_init`, `Priors` holds a `PriorEditor` bound to its `PriorManager` and thin-delegates those methods; on re-init it clears `_editor` before replacing the manager so a failed run cannot leave a stale editor. `SEDInference` facades and the public package export stay unchanged — `PriorEditor` is not in `__all__`. Table rendering uses one formatter modeled on `print_priors` (`modified_mode` `status` | `preview`, always including the Hyperparameters column). Confirmation prompts use `input()` (skip via public `confirm=False`); no injectable confirm hook. Unused `PriorManager.display_priors` / `_format_prior_line` are removed. Lifecycle (load/generate/validate/bootstrap) remains on `Priors`; `.iprior` I/O remains on `PriorManager` (ADR-0002). We rejected exposing `PriorEditor` publicly, wiring presentation through `PriorManager.display_priors`, and changing `set_prior` / `print_priors` signatures in this cut.
