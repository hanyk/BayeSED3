# Launcher first-token paths (version + inspect + run)

ADR-0007 made `bayesed3` a thin binary forwarder. We split on the **first token**: `version` / `--version` report Package version and Binary banner; `results`, `plot`, and `priors` present existing products; **`run`** forwards the rest to the compiled binary (Launcher-owned `--mpi` / `--np` only after `run`). Bare binary argv without `run` is rejected with a short error that rewrites the line as `bayesed3 run <original argv>`. This supersedes ADR-0007’s rule that every non-inspect argv (including `-h` / `--help`) goes to the binary.

**Help / discovery (human + agent):** Empty argv and top-level `--help` / `-h` print the same short Launcher overview (exit 0): one product tagline, then `Version` / `Inspect` / `Run` syntax sketches—no per-entry prose, not a separate “More:” / multi-line subcommand usage block, not the full flag lists, and not binary USAGE. Inspect sketches name the first-token verbs on one line each (`results <outdir> [summary|evidence|…]`, `plot <outdir> [bestfit|posterior]`, `priors list [dir]`); posterior modes and `--cat` / `--cfg` / `--obj` / `--par` / … stay off the overview and appear only on the relevant subcommand usage or when an error must prompt the next step. Incomplete `results` / `plot` / `priors` invocations still print that richer usage (bare `results <outdir>` and bare `plot <outdir>` both print usage; list catalogs only via `results <outdir> catalogs`). `bayesed3 version` and `bayesed3 --version` print the Python package version and the compiled-binary help banner (first `BayeSED3 (…)` line, including Copyright; no separate binary `--version` flag) and do not forward a fit. `bayesed3 run` and `bayesed3 run --help` are equivalent and show binary help. Missing catalog / model configuration / plot-object errors print one CLI line with Available lists inline (no second hint line; no auto-pick). Flag names are fixed at the inspect throw/load boundary (`--cat` / `--cfg` / `--obj` in the message text)—not by patching library strings at print time.

Inspect grammar uses flags for catalog / model configuration / object wherever Results are loaded: `--cat` / `--cfg` / `--obj`. No trailing positional catalog or object names.

- **results query** (`summary` / `evidence` / `par_names` / `objects`): verbs first (stackable), then optional `--cat` / `--cfg` / `--obj` (`--obj` is exact `object_id` on the constructor); optional `--json` on all `results` commands.
- **par_values**: isolated; `--par` required; optional `--cat` / `--cfg` / `--obj` (`--obj` filters via `get_parameter_values`, loose match).
- **catalogs** / **model_configs**: discovery only (`list_catalog_names` / `list_model_configs`), no HDF5 load; `model_configs` takes optional `--cat`; neither combines with other commands.
- **plot**: `bestfit` or `posterior` (not combined); same `--cat` / `--cfg` / `--obj`; `posterior` is `free` / `derived` / repeating `--par` with optional adjacent `--lab`; `derived` may take `--max`. `--cfg` is passed through to `BayeSEDResults` (no CLI pre-check). Multiple model configurations without `--cfg` raise from the library; CLI rewrites that into one `--cfg` line (above). Plot needs a unique object: one object is used silently; several without `--obj` error with one `--obj` line (above)—no `using first` auto-pick. When printing Available catalogs / configs / objects on stderr, at most ten entries (all if ≤10; otherwise first five, `...`, last five)—truncated at the load-error emit boundary, not at raise sites. `results` queries stay catalog-scoped and do not require `--obj`.

They call existing `BayeSEDResults` / `list_prior_types` / `PriorManager.load_prior_file` + `PriorEditor.print_priors` — not a new `.iprior` parser, not fit, not `priors_init`.

We rejected a second console script (easy to miss), a named-fit / YAML surface (a second option language), `priors init` on this path (needs a Model configuration the binary already accepts via `--priors_only`), optional `run` prefix (two equivalent fit spellings), and keeping top-level `--help` as binary help (inspect stayed undiscoverable).

Inspect argv stays hand-written (no argparse / click / typer). Shared `--flag value` walking and usage lines live in `inspect_cli`; `--par` / `--lab` interleaving stays custom.
