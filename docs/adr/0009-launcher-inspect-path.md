# Launcher first-token paths (version + inspect + run)

ADR-0007 made `bayesed3` a thin binary forwarder. We split on the **first token**: `version` / `--version` report Package version and Binary banner; `results`, `plot`, and `priors` present existing products; **`run`** forwards the rest to the compiled binary (Launcher-owned `--mpi` / `--np` only after `run`). Bare binary argv without `run` is rejected with a short error that rewrites the line as `bayesed3 run <original argv>`. This supersedes ADR-0007’s rule that every non-inspect argv (including `-h` / `--help`) goes to the binary.

**Help / discovery (human + agent):** Empty argv and top-level `--help` / `-h` print the same short Launcher overview (exit 0): one product tagline, then `Version` / `Inspect` / `Run` syntax sketches (`version` / `--version`, inspect entries, and `run`)—no per-entry prose, not a separate “More:” / bare-subcommand usage block, not the full flag lists, and not binary USAGE. The sketches are enough to discover next steps; each subcommand’s own usage appears when that command is invoked incomplete (or via its documented bare forms below). `bayesed3 version` and `bayesed3 --version` print the Python package version and the compiled-binary help banner (first `BayeSED3 (…)` line, including Copyright; no separate binary `--version` flag) and do not forward a fit. `bayesed3 run` and `bayesed3 run --help` are equivalent and show binary help. Flag details (`--cat` / `--cfg` / `--obj` / `--par` / `--out` / …) appear only on the relevant subcommand usage or when an error must prompt the next step.

**Inspect loose match** (shared helper): exact → contains → regex; first non-empty hit list wins; candidate order preserved. Used for `--cat`, `--cfg`, `--par`, and `--obj` as specified below. Resolution of `--cat` / `--cfg` happens only in Launcher inspect: match against `list_catalog_names` / `list_model_configs`, then pass the **single exact name** into `BayeSEDResults`. The library’s older Model configuration soft-match is left unchanged for the Python API. Zero hits: one stderr line `Error: No <thing> matching '<pattern>'. Available <list-name>: […]`. Several hits where a single choice is required: one line `Error: Multiple <things> found. Please specify <thing> with --<flag>. Available <list-name>: […]` (`catalog` / `--cat`, `config` / `--cfg`, `object` / `--obj`; Available labels `catalogs` / `configs` / `objects`). No auto-pick and no second `List catalogs` / `List configs` / `List objects` line. Library `ValueError` text is rewritten to the Multiple template at the inspect load boundary when applicable. Trailing Available lists truncate at emit (all if ≤10; otherwise first five, `...`, last five). `results <outdir>` with no subcommand prints results usage (exit 1); list Results catalogs only via `results <outdir> catalogs`. Bare `plot <outdir>` still prints plot usage.

Inspect grammar uses flags for catalog / model configuration / object wherever Results are loaded: `--cat` / `--cfg` / `--obj`. No trailing positional catalog or object names.

- **results query** (`summary` / `evidence` / `par_names` / `objects`): verbs first (stackable), then optional `--cat` / `--cfg` / `--obj`; optional `--json` on all `results` commands. Load is catalog-scoped (and Model configuration–scoped after `--cfg` resolves): **do not** pass `object_id` into the `BayeSEDResults` constructor for these verbs. `--obj` is an optional post-load filter via Inspect loose match over `list_objects()`; **several hits are allowed**. `evidence` / `objects` (and `par_values`, below) filter to the matched ids; `summary` narrows only its objects list (and object-scoped fields if shown); `par_names` and other catalog-level fields ignore `--obj`. `summary` may expose the loaded HDF5 identity as a **filename only**, via a public Results read-only attribute (not private `_hdf5_file`).
- **par_values**: isolated; `--par` required; optional `--cat` / `--cfg` / `--obj` (`--obj` filters via `get_parameter_values`). `--par` and `--obj` use Inspect loose match—not the library’s “compile ⇒ regex” default. Several `--obj` hits remain allowed (same filter shape as today).
- **catalogs** / **model_configs**: discovery only (`list_catalog_names` / `list_model_configs`), no HDF5 load; `model_configs` takes optional `--cat` (loose-matched to one Results catalog name); neither combines with other commands.
- **plot**: `bestfit` or `posterior` (not combined); same `--cat` / `--cfg` / `--obj`; `posterior` is `free` / `derived` / repeating `--par` with optional adjacent `--lab` per `--par` (not all-or-nothing); `derived` may take `--max`. Optional **`--out`**: destination for saving while still showing (`show=True`). One resolved object: `--out` may be a file path or a directory; several resolved objects: `--out` must be a directory (one file per object, names include `object_id` and plot kind). Without `--out`, show only. `--cfg` is resolved in inspect to one exact Model configuration name before construct (not passed through as a raw soft-match string). Without `--cfg`, multiple Model configurations still raise from the library and are rewritten to the `--cfg` Multiple line. **Objects:** one object in the Results set is used silently when `--obj` is omitted; several without `--obj` error with the `--obj` Multiple line—no `using first` auto-pick and no plot-all. When `--obj` is present, Inspect loose match may yield **several** ids: plot each in turn (sequential existing plot calls). `plot posterior --par` uses the same loose match over free ∪ derived names; several param hits are all plotted on that object’s figure; none is an error. A `--lab` is allowed only for that `--par` when loose match yields exactly one name; several param hits with `--lab` error; `--par` without `--lab` may still expand. `results` queries stay catalog-scoped and do not require `--obj`.

They call existing `BayeSEDResults` / `list_prior_types` / `PriorManager.load_prior_file` + `PriorEditor.print_priors` — not a new `.iprior` parser, not fit, not `priors_init`.

We rejected a second console script (easy to miss), a named-fit / YAML surface (a second option language), `priors init` on this path (needs a Model configuration the binary already accepts via `--priors_only`), optional `run` prefix (two equivalent fit spellings), keeping top-level `--help` as binary help (inspect stayed undiscoverable), making `--cat`/`--cfg` exact-only while `--par` is loose (Launcher should share one loose-match ladder), changing the Python Results soft-match in the same step, omitting `--obj` to mean plot every object, `--save` as the plot destination flag (collides with binary `--save_*` booleans; use `--out`), reading private `_hdf5_file` from inspect, and writing a same-stem editable plot script beside `--out` images in this change (image only for now; script export is a later decision).

Inspect argv stays hand-written (no argparse / click / typer). Shared `--flag value` walking and usage lines live in `inspect_cli`; `--par` / `--lab` interleaving stays custom. Valued Inspect flags (`--cat` / `--cfg` / `--obj` / `--par` / `--lab` / `--max` / `--out`) require a value: missing at end of argv, or next token starting with `--`, yields `Error: <flag> requires a value` (do not swallow the following flag as the value). A lone leading `-` on a value is still allowed.
