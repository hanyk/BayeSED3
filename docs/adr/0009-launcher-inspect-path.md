# Launcher first-token paths (version + inspect + run)

ADR-0007 made `bayesed3` a thin binary forwarder. We split on the **first token**: `version` / `--version` report Package version and Binary banner; `results`, `plot`, and `priors` present existing products; **`run`** forwards the rest to the compiled binary (Launcher-owned `--mpi` / `--np` only after `run`). Bare binary argv without `run` is rejected with a short error that rewrites the line as `bayesed3 run <original argv>`. This supersedes ADR-0007’s rule that every non-inspect argv (including `-h` / `--help`) goes to the binary.

**Help / discovery (human + agent):** Empty argv and top-level `--help` / `-h` print the same short Launcher overview (exit 0): one product tagline, then `Version` / `Inspect` / `Run` syntax sketches (`version` / `--version`, inspect entries, and `run`)—no per-entry prose, not a separate “More:” / bare-subcommand usage block, not the full Inspect flag lists (`--cat` / `--par` / …), and not binary USAGE. **Exception:** the Inspect block’s first sketch line may show the Launcher-global `--log-level DEBUG|INFO|WARNING|ERROR|CRITICAL` enum (Inspect only; default `WARNING` when omitted). The sketches are enough to discover next steps; each subcommand’s own usage appears when that command is invoked incomplete (or via its documented bare forms below). `bayesed3 version` and `bayesed3 --version` print the Python package version and the compiled-binary help banner (first `BayeSED3 (…)` line, including Copyright; no separate binary `--version` flag) and do not forward a fit. `bayesed3 run` and `bayesed3 run --help` are equivalent and show binary help. Other flag details (`--cat` / `--cfg` / `--obj` / `--par` / `--save` / `--lab` / `--max` / …) appear only on the relevant subcommand usage or when an error must prompt the next step. Leading `--log-level` before `run` / `version` is an error. Invalid `--log-level` values error with the allowed enum. Inspect applies the chosen level to `bayesed.results` (default `WARNING`), calling `logging.basicConfig` only when the root logger has no handlers so INFO/DEBUG are actually visible; the Results library does not configure logging at import.

**Results / plot / priors usage** (when that path is incomplete or wrong): Usage lines only—**no** trailing `Commands: …` / `results commands: …` footers (verb names already appear on each Usage line or in the single priors Usage line; overview Inspect sketches remain the discovery list). **Results:** one Usage line **per verb**, not a single stackable `<cmd> [<cmd>…]` line. `summary` and `par_names` omit `--obj` on their lines; `evidence` / `objects` / `par_values` include `--obj`. On Results and plot Usage lines, value slots for Inspect loose match flags (`--cat` / `--cfg` / `--obj` / `--par`) use the placeholder `PATTERN`; non-match valued flags keep `TEXT` / `N` (`--lab` / `--max`). Boolean `--save` has no value slot. **Plot / priors:** keep their existing multi-line or single-line Usage shapes, still without a Commands footer. Overview Inspect sketches stay verb-name lists only.

**Inspect loose match** (shared helper): exact → contains → regex; first non-empty hit list wins; candidate order preserved. Used for `--cat`, `--cfg`, `--par`, and `--obj` as specified below. After a `results` verb is parsed (including `catalogs`), a missing or non-directory outdir fails with a directory error (e.g. `not a directory: …`)—not `No catalog matching` and not an empty catalog list. The same gate runs before resolving `--cat` / `--cfg`. Resolution of `--cat` / `--cfg` happens only in Launcher inspect: match against `list_catalog_names` / `list_model_configs`, then pass the **single exact name** into `BayeSEDResults`. The library’s older Model configuration soft-match is left unchanged for the Python API. Zero hits: one stderr line `Error: No <thing> matching '<pattern>'. Available <list-name>: […]`. Several hits where a single choice is required: one line `Error: Multiple <things> found. Please specify <thing> with --<flag>. Available <list-name>: […]` (`catalog` / `--cat`, `config` / `--cfg`, `object` / `--obj`; Available labels `catalogs` / `configs` / `objects`). No auto-pick and no second `List catalogs` / `List configs` / `List objects` line. Library `ValueError` text is rewritten to the Multiple template at the inspect load boundary when applicable. Trailing Available lists truncate at emit (all if ≤10; otherwise first five, `...`, last five). `results <outdir>` with no subcommand prints results usage (exit 1); list Results catalogs only via `results <outdir> catalogs`. Bare `plot <outdir>` still prints plot usage.

Inspect grammar uses flags for catalog / model configuration / object wherever Results are loaded: `--cat` / `--cfg` / `--obj`. No trailing positional catalog or object names.

- **results query** — **one verb per invocation** (not stackable): `summary` | `evidence` | `par_names` | `objects`, then optional flags; optional `--json` on all `results` commands. Load is catalog-scoped (and Model configuration–scoped after `--cfg` resolves): **do not** pass `object_id` into the `BayeSEDResults` constructor. A second query verb is an error. `--obj` is an optional post-load filter via Inspect loose match over `list_objects()` for verbs that are object-scoped; **several hits are allowed**. `evidence` / `objects` (and `par_values`, below) filter to the matched ids. **`summary` and `par_names` ignore `--obj`** (silent if present)—they describe the whole loaded Results set. **`summary`** is an orientation card: outdir, Results catalog, HDF5 **filename** (public Results read-only attribute, not private `_hdf5_file`), HDF5 column / free / derived counts, and the full objects list (truncated when long)—not Evidence and not a mini-report. Human `summary` calls existing `BayeSEDResults.print_summary()`; `--json` emits the same orientation fields. **`evidence --json`** always emits a JSON **array** of row objects with table column names (`ID` plus present `INSlogZ` / `logZ` / `INSlogZerr` / `logZerr`); never a stringified table. Inspect `--json` dumps only JSON-native values (no `default=str` fallback). Tabular commands (`par_values`, name lists) stay arrays; card commands (`summary`, `par_names`) stay objects. **Large object counts (N):** `--json` does not stream, paginate, or hard-cap full dumps of `evidence` / `objects` / `par_values` (no `--obj`); agents and scripts should **orient then narrow**—`summary --json` (truncated `objects` + `n_objects`) or discovery verbs, then `--obj` (Inspect loose match) before pulling tables. Posterior sample chains are not an Inspect `--json` surface (use plot / Python `get_posterior_samples`).
- **par_values**: isolated; `--par` required; optional `--cat` / `--cfg` / `--obj` (`--obj` filters via `get_parameter_values`). `--par` and `--obj` use Inspect loose match—not the library’s “compile ⇒ regex” default. Several `--obj` hits remain allowed (same filter shape as today).
- **catalogs** / **model_configs**: discovery only (`list_catalog_names` / `list_model_configs`), no HDF5 load; `model_configs` takes optional `--cat` (loose-matched to one Results catalog name); neither combines with other commands.
- **plot**: `bestfit` or `posterior` (not combined); same `--cat` / `--cfg` / `--obj`; `posterior` is `free` / `derived` / repeating `--par` with optional adjacent `--lab` per `--par` (not all-or-nothing); `derived` may take `--max`. Plot save is ADR-0017 (boolean `--save`, sidecar, no path); path-valued `--out` is superseded. `--cfg` is resolved in inspect to one exact Model configuration name before construct (not passed through as a raw soft-match string). Without `--cfg`, multiple Model configurations still raise from the library and are rewritten to the `--cfg` Multiple line. **Objects:** one object in the Results set is used silently when `--obj` is omitted; several without `--obj` error with the `--obj` Multiple line—no `using first` auto-pick and no plot-all. When `--obj` is present, Inspect loose match may yield **several** ids: plot each in turn (sequential existing plot calls). `plot posterior --par` uses the same loose match over free ∪ derived names; several param hits are all plotted on that object’s figure; none is an error. A `--lab` is allowed only for that `--par` when loose match yields exactly one name; several param hits with `--lab` error; `--par` without `--lab` may still expand.

They call existing `BayeSEDResults` / `list_prior_types` / `PriorManager.load_prior_file` + `PriorEditor.print_priors` — not a new `.iprior` parser, not fit, not `priors_init`.

We rejected a second console script (easy to miss), a named-fit / YAML surface (a second option language), `priors init` on this path (needs a Model configuration the binary already accepts via `--priors_only`), optional `run` prefix (two equivalent fit spellings), keeping top-level `--help` as binary help (inspect stayed undiscoverable), making `--cat`/`--cfg` exact-only while `--par` is loose (Launcher should share one loose-match ladder), changing the Python Results soft-match in the same step, omitting `--obj` to mean plot every object, `--save` as a *path-valued* plot destination (collides with binary `--save_*`; ADR-0017 later takes `--save` as a plot-only boolean with no path), reading private `_hdf5_file` from inspect, writing a same-stem editable plot script beside saved images in this change (image only for now; script export is a later decision), stacking results query verbs in one argv (ambiguous with `--obj`; prefer one verb per run), filtering `summary` objects by `--obj` (orientation card is whole-Results; use `objects` / `evidence` for subsets), and trailing `Commands: …` footers on results / plot / priors usage (redundant with per-line verb names and overview sketches).

Inspect argv stays hand-written (no argparse / click / typer). Shared `--flag value` walking and usage lines live in `inspect_cli`; `--par` / `--lab` interleaving stays custom. Valued Inspect flags (`--cat` / `--cfg` / `--obj` / `--par` / `--lab` / `--max`) require a value: missing at end of argv, or next token starting with `--`, yields `Error: <flag> requires a value` (do not swallow the following flag as the value). A lone leading `-` on a value is still allowed.
