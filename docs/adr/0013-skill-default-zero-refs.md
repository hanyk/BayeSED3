# Skill refs: default zero; `bayesed3 run` only on delivery

Skill eval Phase 2 showed Prefer entry selection was reliable, but agents opened `binary-cli.md` / extra model refs on ordinary `SEDInference` fits (weak context pointers). We decide: default new fit uses `SKILL.md` Skeleton + FAQ with **zero** `skills/references/*` opens; open a ref only when its stated gate fires. `bayesed3 run` / `binary-cli.md` only when the user delivers an `--import` options file, a full compiled-binary argv string, or **explicitly** requires Launcher `run` forwarding — mentioning the string `bayesed3 run` is not enough. Prefer is positive entry rules plus one guardrail: do not open `binary-cli.md` unless that gate fires. Sampling knobs (`nlive` / `seed` / `efr` / `Ntest`) live in the FAQ and `advanced-run-modes.md`, not `binary-cli.md`. We rejected “open any tree-listed ref by default” (fan-out) and stuffing a full API encyclopedia into the skill (ADR-0001). Executable pointer table: `skills/SKILL.md`.
