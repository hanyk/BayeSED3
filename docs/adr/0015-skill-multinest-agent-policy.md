# Skill MultiNest: don’t touch by default; glossary file gated; no `configure_multinest` patch

Agents were seeing four MultiNest “defaults” (`MultiNestParams` / `--help` at `nlive=100,efr=0.1`; `configure_multinest()` at `nlive=400,efr=0.3`; spectroscopic worked lines at `ceff=1,nlive=40`; FAQ `configure_multinest(nlive=40)` which overlays the method profile). We decide: unattended fits do not set MultiNest (library/`--help` defaults); a user “quick test” is `Ntest=1` plus `nlive=40` only (`MultiNestParams(nlive=40)` or the `--help` tuple with the 4th slot changed)—not `configure_multinest`, which overwrites `efr`/`fb`/`outfile`; “production” / “evidence” does not bump `nlive` to 400 or `efr` to 0.3 (`nlive` is sampling resolution, cost scales with it; Han et al. 2023’s CSST balance is `efr=0.1,nlive=50`, and noisy photometry can worsen with extra live points); raise `efr` to 0.8 only for faster parameter estimation; raise `nlive` only when the user wants stabler evidence. Assemble-run worked lines omit `--multinest` (binary defaults). Slot *meanings* live in `references/multinest-params.md` (15 rows, BayeSED order—not `README_multinest.txt`, whose `tol`/`efr` are swapped vs `--multinest`); `binary-cli.md` keeps only the index and a pointer. Open that glossary only when the user changes a field beyond the FAQ quick test or asks what a slot is (not on every `bayesed3 run`). We rejected dumping README into `SKILL.md`, a production magic `nlive=400`, scaling `nlive` by `n_free` in this cut, and changing `configure_multinest` to keyword-patch. This does not reopen a second *assembly cookbook* (ADR-0014); the new file is a gated glossary.
