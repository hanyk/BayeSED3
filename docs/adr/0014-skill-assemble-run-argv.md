# Skill assemble-run: first-class Run argv, live `--help`, not the default

Ordinary new fits stay `SEDModel` + `SEDInference` → Results with zero `references/*` (ADR-0001, ADR-0013). Assembling Launcher **Run argv** (`bayesed3 run …`) is a first-class branch, not an escape hatch, when any Prefer `run` gate holds: the user wants a copy-paste `bayesed3 run` command or delivers `--import` / a full argv string; the deliverable is a shell command (job script / one-liner), not a Python snippet; or `bayesed3 run --help` lists a flag that is not a `BayeSEDParams` field and the user rejects `import_files`. Flag shapes come from live `bayesed3 run --help`, not `SKILL.md`. `binary-cli.md` is the assembly cookbook (`igroup`/`id`, `iscalable`, SSP fields, model names, worked `bayesed3 run` lines)—not a flag encyclopedia. After `run`, Inspect is the Done criterion; `BayeSEDResults(outdir)` is optional when the session already uses Python or needs GetDist. Assemble-run step-3 Done is component-complete against the user request and the matching worked line (galaxy vs QSO), not galaxy `--ssp`/`--sfh`/`--dal` only. The compiled binary writes missing `.iprior` files during `bayesed3 run` and fits with those defaults (no dummy Input catalog, no `--priors_only` loop, no iteration cap); `--z` / `--sys_err_*` may be on Run argv; custom bounds use Python `set_prior`. We rejected dumping `--help` into `SKILL.md`, making Run argv the default fit path, jumping because Params assembly looks harder or faster, treating `run` as a no-Python path, wrapping `priors init|set` in this cut, hand-editing `.iprior` on this branch, copying Python `priors_init`’s dummy Input catalog / `--priors_only` loop onto Launcher `run`, and a second *assembly cookbook* beside `binary-cli.md`. ADR-0015 adds a gated MultiNest *glossary* (`multinest-params.md`), not a second cookbook. This restates ADR-0013’s Prefer `run` gate (no longer “escape hatch only”) while keeping “do not open `binary-cli.md` on ordinary Python fits”; the skill’s own mention of `bayesed3 run` is not a gate.
